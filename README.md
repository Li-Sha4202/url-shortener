# 🔗 URL-Shortener

Сервис для сокращения длинных ссылок с возможностью создания как случайных, так и пользовательских коротких кодов.  
Поддерживает регистрацию и аутентификацию пользователей, срок действия ссылок, статистику переходов (количество переходов, время первого перехода, время последнего перехода и статистика переходов по дням) и возможности для администраторов.

Проект написан на **Python** с использованием **FastAPI** и **PostgreSQL**, упакован в **Docker** и готов к быстрому развёртыванию.

---

## 📋 Основные возможности

- **Сокращение ссылок** – автоматическая генерация короткого кода (алгоритм Base62) или создание собственного кастомного кода.
- **Управление сроком действия** – ссылка может быть бессрочной или истекать (по умолчанию 1 день, максимум 365 дней).
- **Статистика переходов** – для каждой ссылки сохраняются:
  - дата первого и последнего клика,
  - общее количество кликов,
  - количество переходов по дням,
  - для администраторов доступна агрегированная статистика по всем ссылкам.
- **Пользовательские аккаунты** – регистрация и вход (JWT-аутентификация), возможность редактировать и удалять свои ссылки.
- **Гостевой доступ** – можно создавать короткие ссылки без регистрации.
- **Безопасность** – пароли хэшируются с помощью **Argon2**, JWT-токены подписываются секретным ключом.
- **Готовый API** – интерактивная документация Swagger (`/docs`) для тестирования всех эндпоинтов.

## 🧩 Особенности архитектуры

- **Асинхронная работа** – все операции с БД выполняются асинхронно (FastAPI + asyncpg).
- **Чистая архитектура** – код разделён на слои (`api` – маршруты, `service` – бизнес-логика, `repository.py`** — работа с БД, `models` – SQL-модели, `schemas` – Pydantic-схемы, `core` – конфигурация и утилиты).
- **Миграции** – выполняются автоматически при старте контейнера через `prestart.sh` (Alembic).
- **Тестовая среда** – отдельный контейнер с тестовой БД, тесты запускаются изолированно и автоматически завершаются.

## 🚀 Быстрый старт

### Требования
- Docker и Docker Compose (рекомендуется)
- (Опционально) Python 3.13+ и Poetry для локального запуска без Docker


### Запуск через Docker (рекомендованный способ)

Клонируйте репозиторий:

```bash
git clone https://github.com/Li-Sha4202/url-shortener.git
cd url-shortener
```
### Переменные окружения

В файл `.env.example` в корне проекта добавьте секретный ключ для создания JWT-токенов, и уберите подпись `.example`:

```env
APP_CONFIG__DB__URL=postgresql+asyncpg://user:password@pg:5432/shortener
APP_CONFIG__JWT__SECRET_KEY=ваш_секретный_ключ
APP_CONFIG__RUN__PUBLIC_URL=http://localhost:8000
```
JWT-ключ можно сгенерировать разными способами, можно к примеру либо через OpenSSL, если он у вас установлен:
```OpenSSL
openssl rand -base64 32
```
Либо можно использовать Python:
```Python
python -c "import secrets; print(secrets.token_urlsafe(32))"
```


Запустите все сервисы:

```bash
docker-compose up -d
```

При первом запуске автоматически:
- установятся зависимости через Poetry,
- применятся миграции Alembic,
- поднимутся PostgreSQL, PGAdmin4 и само приложение.

Приложение будет доступно по адресу: [http://localhost](http://localhost).

Интерактивная документация API: [http://localhost/docs](http://localhost/docs)

## 🧰 Использование интерактивной документации API /docs
Эндпоинты в интерактивной документации достаточно просто использовать, они все работают по одному принципу, покажу на примере регистрации:

### 🖥️ Регистрация
Регистрация происходит через роут - **/users/register User Register** - вверху страницы, нажимаем его, чуть ниже справа появляется кнопка - **Try it Out** - также её нажимаем, и перед вами появляются данные, которые требуются для заполнения, они изначально заполнены примерными данными, заполняете как требуется, либо оставляете как есть: 
```json   
{
  "username": "string",
  "email": "user@example.com",
  "password": "stringst"
}
```
Нажимаем на длинную голубую кнопку **Execute**. После этого листаете немного вниз, появится окно результата запроса и код выполнения:
**201 Response body**
```json
{
  "username": "string",
  "email": "user@example.com",
  "created_at": "2026-11-09T17:39:58.432022Z",
  "is_admin": false
}
```

### ❗ Важно
В /docs роуты справа обозначены полупрозрачным замком 🔓, это значит, что требуется авторизация, кнопка авторизации находится в верхней части страницы справа,
`Зелёная кнопка [Authorize 🔓]`, в ней введите ПОЧТУ, и ПАРОЛЬ зарегистрированного пользователя, пример:
- user@example.com
- stringst

Не влияет на создание ссылки, т.е. на роут /links/create - Create New Link, можно и без авторизации создавать ссылку, соответствует смыслу проекта 🙃. После этого замки должны стать жирными и закрытыми 🔒.


### ➡️ Redirect по ссылке
При создании ссылки в ответе автоматически создаётся полная ссылка перехода по ссылке, можно перейти по ней, выделив ссылку и нажав на появившуюся кнопку *Перейти* (на примере Yandex Browser), либо можно ввести вручную в строке поиска браузера:
`http://localhost/{short_code вашей ссылки}` - Далее происходит редирект по ссылке, пример - `http://localhost/examplecode`

### ⏲️ Бессрочная ссылка
Во премя создания ссылки автоматически подставляется срок жизни `"expires_at": 1`, это значит что ссылка будет "жить" один день, чтобы сделать её бессрочной, достаточно удалить строку `"expires_at": 1`, т.е.:
```json
  Было:   
  {                                                 
  "original_url": "https://example.com/",                 
  "short_code": "g9QN_1NNslfm2v",                         
  "expires_at": 1                          
  }
```
```json
  Стало:
  {
  "original_url": "https://example.com/",
  "short_code": "g9QN_1NNslfm2v"  <-- запятую тоже нужно удалить
  }
```

## 👨‍⚖️ Создание админа

Есть возможность создать админа, и делается это только через **PGAdmin4**. Напомню, PGAdmin4 - это СУБД (Система управления базами данных), через которой можно управлять данными нашей БД - PostgreSQL. У SQL-модели User есть галочка *is_admin*, т.е. как раз права админа, изначально она False, поэтому через СУБД мы поставим галочку True, чтобы пользователь стал админом. PGAdmin4 находится по ссылке - `http://127.0.0.1:5050`.
При переходе по ссылке от вас потребуется ввести пароль - `admin`. (PGAdmin4 запускается долго, и может быть при переходе у вас выйдет ошибка, по типу - Соединение установлено, но сервер не отправил ничего в ответ - подождите немного, пока СУБД запустится, и перезагрузите страницу).

### Теперь нужно найти и зарегистрировать нашу Базу Данных

Нужно нажать правой кнопкой **Servers -> Register -> Server**.
Появляется окно, которое сразу требует от вас ввести название сервера в строке **Name**, можно ввести абсолютно любое название сервера. В моём случае я ввожу - **pg**.
После написания названия сервера, в верхней части окна переходим на следующую вкладку - **Connection**, и вводим следующие значения:
- Host name/address - **pg**
- Port - **5432** (стоит изначально, поэтому не трогаем)
- Maintenance Base - **shortener**
- Username - **user**
- Password - **password**
- Нажать на кнопку **Save password?**, она загорится голубым.
И нажимаем внизу окна кнопку `💾Save`.
Мы зарегистрируем нашу базу данных в СУБД, и сможем управлять данными в ней.

### Далее находим таблицы БД

Нажимаем на стрелку **>** слева от **Servers**, далее также на стрелки нажимаем - **pg** *(Название вашей БД)* **-> Databases -> shortener -> Schemas -> Tables**.
Здесь находятся 4 таблицы:
- **alembic_version** - список версий таблиц БД, созданные через alembic
- **click_log** - таблица с детальными данными перехода по ссылке (Устройство, Браузер, IP)
- **link** - таблица с данными о ссылке и базовая статистика (Количество переходов и.т.д.)
- **user** - таблица с данными пользователей, Она нам и нужна.
Нажимаем правой кнопкой по **user -> View/Edit Data -> All rows**.
Перед нами появятся данные этой таблицы. Если вы регистрировали пользователя, в таблице должны появится данные о нём. Нам нужен последний столбец **is_admin**, нажимаем 2 раза по нему, начинаются изменения данных, и нажимаем по квадратику пока не появится галочка ✅, нажимаем в сторону, чтобы выйти из режима изменения данных, и нажимаем **F6** для сохранения данных.
Если вы хотите увидеть изменения данных в таблице, нажмите на окно с таблицами и данными, чтобы переместить фокус, и нажмите на **F5**.
### Поздравляю, вы создали админа!


### 🧪 Тестирование

Тесты разделены на три категории и запускаются автоматически в изолированном контейнере.

Unit-тесты – проверка хеширования, генерации токенов, Base62 и прочих утилит.

Интеграционные тесты – тестирование CRUD-операций с реальной БД (используется тестовая БД).

E2E-тесты – полные сценарии работы с API (создание ссылки, редирект, статистика).

После завершения тестов тестовый контейнер автоматически останавливается.
